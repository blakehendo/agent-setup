# Daily Launch

Blake's 9:15–9:30 ritual. Three tasks, one per block, written down before the day starts.

## Steps

1. **Read yesterday.** Check `notes/` for the most recent dated file and `BIG3.md` for yesterday's entry. If yesterday's Big 3 had unfinished items, surface them first — they are candidates for today.

2. **Check the plan.** The SessionStart hook already printed the current week's BUILD focus, LEARN topic, and the week's question. Use that.

3. **Check the calendar** if the Google Calendar MCP is connected — an interview call or a displaced block changes what's realistic today.

4. **Propose the Big 3.** Exactly three, one per block:
   - 🟦 **BUILD** — something shippable in 2.5 hours. If it isn't shippable in 2.5 hours, it's the wrong task; cut it down.
   - 🟨 **LEARN** — one concept, ending in the 200-word note.
   - 🟪 **SHIP** — push, post, apply, or reply. Something that leaves the machine.

5. **Make them falsifiable.** "Work on the eval harness" is not a task. "Promptfoo config runs three models against five prompts and prints a table" is a task. Rewrite anything vague.

6. **Append to `BIG3.md`** under a `## YYYY-MM-DD` heading, with unchecked boxes.

## Rules

- Three. Not four. If a fourth is genuinely urgent, something else drops — say which.
- Don't accept a BUILD task that has an unresolved unknown in it. Split the unknown into its own 30-minute spike first.
- If yesterday's BUILD item slipped, ask once whether it's the right task before rolling it forward. Twice-slipped tasks are usually wrong, not delayed.
